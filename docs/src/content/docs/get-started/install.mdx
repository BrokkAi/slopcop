npm, PyPI, the release archive, and the shell and PowerShell installers all
install the same release binary for macOS, Linux, and Windows on x64 and arm64,
so `slopcop version` reports which release it came from. The Go toolchain can
build that binary from source instead.

| Channel | Platforms | Needs |
| --- | --- | --- |
| npm | macOS, Linux, Windows | Node 22 or newer |
| PyPI | macOS, Linux, Windows | Python 3.9 or newer |
| Release archive | macOS, Linux, Windows | nothing |
| Shell installer | macOS, Linux | curl |
| PowerShell installer | Windows | PowerShell |
| Go | built from source | Go 1.25 or newer |

<Tabs syncKey="install">
  <TabItem label="npm">
    ```console
    npm install --global @brokkai/slopcop
    slopcop --help
    ```

    The tarball carries the release binary for every supported platform, so it
    needs no Go toolchain. `npx @brokkai/slopcop` runs it without installing it.
  </TabItem>
  <TabItem label="pip">
    ```console
    pip install brokk-slopcop
    ```

    `pipx install brokk-slopcop` or `uv tool install brokk-slopcop` puts it in an
    environment of its own. The wheels carry the release binary, so no Go
    toolchain is needed either. The package is `brokk-slopcop` because PyPI
    already has an unrelated project named `slopcop`; the command it installs is
    still `slopcop`, and `python -m brokk_slopcop` runs the same binary.
  </TabItem>
  <TabItem label="Shell">
    ```console
    curl -fsSL https://raw.githubusercontent.com/BrokkAi/slopcop/master/install.sh | sh
    ```

    It takes the latest release, verifies the archive against `checksums.txt`,
    installs `slopcop` to `$HOME/.local/bin`, and adds that directory to the
    shell profile. `SLOPCOP_VERSION`, `SLOPCOP_INSTALL_DIR`, and
    `SLOPCOP_NO_MODIFY_PATH` override its defaults.
  </TabItem>
  <TabItem label="PowerShell">
    ```powershell
    irm https://raw.githubusercontent.com/BrokkAi/slopcop/master/install.ps1 | iex
    ```

    It takes the latest release, verifies the archive against `checksums.txt`,
    installs `slopcop.exe` to `%LOCALAPPDATA%\Programs\slopcop`, and adds that
    directory to the user `Path`. `SLOPCOP_VERSION`, `SLOPCOP_INSTALL_DIR`, and
    `SLOPCOP_NO_MODIFY_PATH` override its defaults.
  </TabItem>
  <TabItem label="Release archive">
    Each release publishes `slopcop_v<version>_<os>_<arch>.tar.gz` (`.zip` on
    Windows) holding the binary, `README.md`, and `LICENSE`, plus a
    `checksums.txt` covering every archive. Download them from
    [the latest release](https://github.com/BrokkAi/slopcop/releases/latest) and
    check the sha256 before unpacking:

    ```console
    ver=$(curl -fsSL https://api.github.com/repos/BrokkAi/slopcop/releases/latest | sed -n 's/.*"tag_name": *"v\([^"]*\)".*/\1/p')
    os=linux; arch=amd64   # darwin/arm64 on Apple silicon
    base=https://github.com/BrokkAi/slopcop/releases/download/v$ver
    curl -fsSLO "$base/slopcop_v${ver}_${os}_${arch}.tar.gz"
    curl -fsSLO "$base/checksums.txt"
    grep "${os}_${arch}" checksums.txt | sha256sum -c -   # shasum -a 256 -c - on macOS
    tar -xzf "slopcop_v${ver}_${os}_${arch}.tar.gz" slopcop
    sudo install -m 755 slopcop /usr/local/bin/slopcop
    ```
  </TabItem>
  <TabItem label="Go">
    ```console
    go install github.com/BrokkAi/slopcop/cmd/slopcop@latest
    ```

    Go 1.25 or newer is required to build. A plain `go install` reports `dev` as
    its version; in a clone, `make install` stamps the version from
    `git describe`.
  </TabItem>
</Tabs>

## Local review requirements

The default check needs Node.js with `npx` and existing reviewer harness
logins. DeepSeek ACP uses `DEEPSEEK_API_KEY` unless configured with a key file.
Use `--mode static` to run only the hosted check, including in CI without
reviewer logins.

## Check the install

```console
slopcop version
```

prints the release the binary came from. `slopcop --help` lists every command.
Nothing else is needed before [signing in](/account/sign-in/).

## Upgrade notices

Every response from the service names its newest release. When that is newer
than the running build, the CLI prints one line on stderr, never stdout, so
`--format json` and `sarif` stay clean:

```text
slopcop v0.0.9 is available (you have v0.0.7). Upgrade: npm install --global @brokkai/slopcop@latest
```

The command follows the channel the binary was installed through (npm, npx,
pip, pipx, or uv), judged by where it lives, and links to the install
instructions otherwise. The notice prints at most once a day. `dev` builds, Stop
hook runs, and runs with `SLOPCOP_NO_UPDATE_NOTICE` set to any non-empty value
never print it.

A service that no longer accepts a version answers `client_outdated`, which
exits `2`: upgrade through the channel you installed from and run the check
again.

## Upgrade

Use the channel you installed from:

| Channel | Upgrade |
| --- | --- |
| npm | `npm install --global @brokkai/slopcop@latest` |
| pip | `pip install --upgrade brokk-slopcop` (or `pipx upgrade brokk-slopcop`, `uv tool upgrade brokk-slopcop`) |
| Shell or PowerShell installer | run the installer again |
| Release archive | download the new archive and replace the binary |
| Go | `go install github.com/BrokkAi/slopcop/cmd/slopcop@latest` |

A check updates an existing agent skill copy to the one bundled in
the new binary, and tells you which files changed. See
[The agent skill](/agents/skill/).
