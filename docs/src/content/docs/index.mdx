<section class="sc-section">
  <p class="sc-eyebrow">How a check works</p>
  <h2>One command, one request, one report.</h2>
  <p>There is no local analyzer. The CLI sends one git patch to the hosted service, the service applies it to your base commit and runs <a href="https://github.com/BrokkAi/bifrost">Bifrost</a> over the files the change writes, and your agent reads the result.</p>
  <div class="sc-flow not-content">
    <article>
      <small>01 / your machine</small>
      <h3>Your coding agent runs <code>slopcop</code></h3>
      <p>Claude Code, Codex, opencode, or anything with a shell. The bundled skill tells it how.</p>
    </article>
    <article>
      <small>02 / the patch</small>
      <h3>The CLI diffs the working tree</h3>
      <p>From the merge base with your upstream branch: unpushed commits, unstaged edits, untracked files.</p>
    </article>
    <article>
      <small>03 / the service</small>
      <h3>Its own clone, Bifrost on top</h3>
      <p>The patch is applied at the base commit. Your code is read, never run, and never sent to a language model.</p>
    </article>
    <article>
      <small>04 / the loop</small>
      <h3>New findings fail the check</h3>
      <p>The agent fixes them and checks again until none are left. Findings already in the code never fail it.</p>
    </article>
  </div>
</section>

<section class="sc-section">
  <p class="sc-eyebrow">What to expect</p>
  <h2>Answers it can prove.</h2>
  <CardGrid stagger>
    <Card title="Traced to a rule" icon="approve-check">
      Each finding names the rule that raised it, its severity, its certainty, and the file and line. The analysis is static, deterministic, and runs the same way twice.
    </Card>
    <Card title="Across files" icon="random">
      Data flow is traced through the files the change writes: a request parameter that reaches a SQL query three files later is one finding, with the path that proves it.
    </Card>
    <Card title="Never a false all-clear" icon="warning">
      A rule that cannot finish makes the check incomplete, never clean. The report says what was not covered, so your agent never reads silence as safety.
    </Card>
    <Card title="Built for agents" icon="seti:shell">
      No prompts, one request, a closed exit-code contract, and JSON or SARIF output. An agent can run it after every edit without a human in the loop.
    </Card>
  </CardGrid>
</section>

<section class="sc-section">
  <p class="sc-eyebrow">Exit codes</p>
  <h2>The contract an agent reads.</h2>
  <div class="sc-exit not-content">
    <div><b>0</b><span>Clean. The check completed and the change added no finding.</span></div>
    <div><b>1</b><span>Findings. The change added one. Fix it and check again.</span></div>
    <div><b>2</b><span>Incomplete, or the CLI or service failed. Never an all-clear.</span></div>
    <div><b>3</b><span>Still running when the timeout ran out. Run the same check again.</span></div>
    <div><b>4</b><span>Refused, and only a person can clear it. Read the code and remedy.</span></div>
  </div>
